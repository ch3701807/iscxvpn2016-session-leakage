# G01 兄弟抓包判定规则（预注册）

本规则在打开任何原始抓包内容、计算兄弟文件证据之前固定。登记日期：2026-11-06。后续如需改变，另建偏离记录，不覆盖本文件。当前阶段只盘点了文件名、大小和既有代码；没有使用 Muse 的兄弟核查结论。

1. 会话名：文件 stem 去掉末尾的一个 a/b/A/B，同时去掉紧邻其前的一个下划线。其余字符保持原样，不进行拼写纠正。后缀合并组中所有文件两两比较；另在每个应用类别内，以首包时间升序、文件名破同时间平局，比较相邻文件，合并重复候选对。
2. 文件元数据：记录物理包序的首末时间及最小最大时间、记录包数、链路类型、snaplen。pcapng 按 section/interface 编号记录每个接口的链路类型、snaplen 和时间分辨率；不保存接口名称、描述、MAC 或地址。
3. 时间：区间 [最小包时间,最大包时间] 相交为重叠（间隔 0）；不相交时以较早区间末端到较晚区间起点为间隔。0 < 间隔 <= 60 秒为相接；> 60 秒为分离。以下 a/b 代表时间先后，不能由文件名后缀代替时间顺序。
4. 共有连接：TCP、UDP 分别按双向规范化五元组（地址、端口、协议）计算唯一交集数。地址和端口仅驻留内存，发布数据只含计数；若需要连接标识，则地址采用独立随机盐 SHA-256，盐仅存本地且不进交付包。连接号不得保留原始地址或端口。
5. 切开 TCP：仅考虑时间非重叠且间隔 <= 60 秒、共有的 TCP 五元组，按每个传输方向计算 TCP 序号区间（payload 长度，加 SYN/FIN 各占一个序号，模 2^32）。精确重传的方向、seq、ack、flags、payload 哈希完全相同则合并；乱序按序号区间重建已覆盖区间，不以物理最后一个重传包冒充连接末端。要求 b 的首个新序号区间紧接 a 的最后连续区间，且 ACK 与反向已观测的边界一致（或纯 ACK 的 seq/ack 同时对齐已观测边界）；不得跨缺口、跨序号复用的新 SYN 握手、或跨未确定的序号回绕推定连续。不能证实的连接仅记共有，不记切开。另保存重传数、乱序数和无法确定边界数。
6. 相同包：按完整 captured packet 字节 SHA-256，包含链路层、去除抓包记录时间戳和容器头。采用多重集交集数 sum(min(n_a(h),n_b(h)))；分别给 shared/n_a、shared/n_b，以及 shared/min(n_a,n_b)。链路类型不同也按原始整包字节严格比较，不做去头或重写。
7. 疑似重复抓包：两文件均至少 100 个包，且 shared/min(n_a,n_b) >= 0.90 时标记；作为独立标记保留底层会话判定，不以重复标记抹掉证据。
8. 相同特征流：按本任务 v3 规则独立抽取并清洗、屏蔽 SNI 后，拼接 float32 的 seq(50)、iat(50)、raw(256)、stat(6) 的 C-order 字节计算严格相等；不含标签、文件、会话、流 ID。以多重集交集数统计两文件相同特征流数，不对浮点取整。不对深度模型按折拟合的标准化输出作跨文件比较。
9. 判定优先级：切开的 TCP >= 1，或时间相接且 TCP/UDP 共有五元组总数 >= 1，记“确定同一会话”；时间相接或重叠且没有共有连接，记“可能”；时间分离且没有共有连接，记“无证据”。题述未覆盖的“重叠或分离但有共有连接，未证实切开”单列“共有连接但不足判定”，不强行升级为确定，保持判定阈值。
10. 重建会话：以后缀分组为起点，仅新增“确定同一会话”跨组边，按连通分量合并。列出每条新增边的证据，不使用模型分数决定是否合并。之后重跑指定 RF(seq+iat)、7、11 的三种子实验。
11. 清洗端口：DNS 53；mDNS 5353；LLMNR 5355；NBNS/NetBIOS 137/138/139；SSDP 1900；DHCP 67/68/546/547；NTP 123；SNMP 161/162；WS-Discovery 3702。任一端命中即去掉该双向流；任一方向目的为组播、有限广播，或按抓包可确定的链路广播时去掉。地址和端口不写入特征文件。
12. 提取保持 v2 的双向规范化、空闲超时 > 120 秒、包长上限 1500、至少 5 包、按原排序截取前 50 包及原六维统计定义。raw 为这 50 包按 v2 排序拼接的传输层 payload 的前 256 字节，/255。TLS 解析仅使用这些可见字节，按记录和握手字段边界解析 ClientHello 的 server_name 扩展；只置零落在可见范围内的主机名字节，不改变其它字节或长度，不猜测未完整可解析的结构。报告可解析 ClientHello 流数、含 SNI 流数和实际改变的非零字节数。
13. 所有阶段遇到用户指定停机条件即记录并停止；不能把未完成字段填为 0 或当成否定结论。
